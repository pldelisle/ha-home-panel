Why the dense 27B is out

Prefill runs at about 90 tok/s. A cold house prompt (11,357 tokens) takes about 2 minutes and a 48K prompt takes 10–15 minutes. Even with the prompt cached, answers take 3–5 s.

Caveats

Problems with the run itself

  1. Qwen3.8-27B oQ4's “max4 + chunked prefill” is a spurious win.The max4 result came from noise in the single-stream MTP measurement (21.2 vs 16 tok/s), not from concurrency: with 2 or 4 requests the total stayed around 10 tok/s for every setting. With max4 carried into the next stage, unchunked mixed work fell apart (206 s TTFT, 4.6 tok/s), and chunking then fixed a problem the bad max4 pick caused. Re-run both stages for that model.
  2. Script bug: the 5 % MIN_GAIN guard never runs in the memory stage.safe is the first option and always fails, so base_score stays None (omlx.py, around line 611) and the stage keeps the raw maximum. That's how Gemma ended up on custom24 (220) over aggressive (212), a 4 % difference. Compare against the best option that ran instead of the first one in the list.
  3. The “fits” check rests on one noisy swap reading.A run fits only if swap grows by less than 256 MB, and swap is measured system-wide while a VM runs. Qwen3.6 oQ3 at 48K counted as not fitting with custom24 (+629 MB) and as fitting with custom26 (+203 MB). The many negative swap values show the reading follows the whole system, not oMLX.
  4. “First s” in the HA table compares a cold start with a warm one.mtp_off always runs first, so it pays for the model load and the full ~11K-token prefill (27–123 s). mtp_on then reuses 11,350 cached tokens. The column says nothing about MTP.
  5. The report understates the HA prompt.It says ~6K tokens; the measured size is 11,357 (11,468 for Gemma).
  6. Gemma's vlm_mtp_on run reports “Lightning MTP” as its backend.Either the VLM MTP path never ran or the label is wrong. The MTP stage did show different acceptance rates for the VLM options (0.73–0.86 vs 0.80), so the label is the more likely culprit.
  7. The tool suite is small (10 cases).The ranking still looks solid because every failure repeats across both quants and both MTP settings.
