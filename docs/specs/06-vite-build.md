# Spec 06: Vite build, ES modules replace text splicing

Parent: [production-grade-refactor.md](production-grade-refactor.md), phase 1.
Depends on: phase 0 complete ([02](02-screenshot-baselines.md), [03](03-lint-and-format.md), [04](04-vitest-and-checkjs.md), [05](05-changesets-renovate-codeql.md)). Blocks: [07 npm packages](07-npm-packages-replace-vendor.md), [08 bundled font](08-bundled-font.md).
Ships as: one pull request, a patch release, no visible change.

The key words MUST, MUST NOT, SHOULD, SHOULD NOT and MAY are to be read as in RFC 2119.

## Problem Statement

The build is a script that reads the main class as text and replaces five placeholders (`/*__CONFIG__*/`, `/*__STACK__*/`, `/*__FR__*/`, `/*__AUTO__*/`, `__CSS__`, `'__VERSION__'`) with the contents of other files. The pieces share one global scope, so nothing is a module, nothing is imported, the type checker and the linter cannot follow a reference across files, and the tests load pure modules by evaluating source text. The 571 KB output is not minified, has no source map and no tree shaking, so a stack trace from a tablet points into a 4,386-line file at a line that does not exist in the source.

## Solution

Make every source file an ES module with explicit imports and exports, and build with Vite in library mode: one minified ES module entry with a source map beside it, the CSS imported as text and adopted in the same order as today, the version injected from `package.json`. The vendor libraries are still copied and lazy-loaded exactly as today; spec 07 turns them into packages. The screenshot baselines prove nothing changed.

## User Stories

1. As a maintainer, I want to open a source file and see what it imports, so that I can follow a reference without searching for a placeholder.
2. As a maintainer, I want a stack trace from the tablet to point at a source line, so that a bug report is actionable.
3. As a household member, I want the panel to download less, so that it loads faster on the tablet's first paint.
4. As a maintainer, I want unit tests to `import` the pure modules, so that the source-text loader can go.
5. As a maintainer, I want a size budget enforced from the first minified build, so that the bundle never creeps unnoticed.
6. As an agent thread, I want `npm run dev` to rebuild on save, so that I can iterate with the test house open.

## Implementation Decisions

### Module layout (JavaScript, not yet TypeScript)

- Files keep their current names and content; only module plumbing changes. `src/main.js` is the new entry: it imports the class file and defines the custom element. The class file (`home-panel.src.js`, renamed `home-panel.js`) imports what it used from the spliced files.
- `src/config.js` exports `resolveConfig`, `guessIcon`, `DEFAULT_ENTITIES`, `ENTITY_ALIAS`, `ROOM_ICONS`. `src/stack.js` exports `pickStack`, `inHours`, `reminderLeft`, `STACK_TURN_MS`.
- `src/i18n/fr.js` and `src/i18n/fr-map.js` become one module, `src/i18n/fr.js`, exporting the functions the class calls (`frText`, `frStart`-related helpers, the `FR` flag accessors) and `FR_MAP`. The French layer's module-level state (`FR`, the name cache) stays module-level in this PR; moving it into a store is phase 2.
- `src/auto.js` already builds an object of methods assigned onto the class prototype; it becomes a module exporting that object and the class file installs it with one `Object.assign(HomePanel.prototype, autoMethods)` line. Its module-level helpers that the class also uses (`auDur`, `auClock`) are exported explicitly.
- Helpers that were shared through the single global scope (`st`, `ok`, `num`, `attr`, `esc`, `TZ`, `hass`, the formatting helpers) are the hard part. They live at the top of the class file today and `auto.js` and `fr.js` read them as globals. In this PR they move to `src/legacy/globals.js`, which exports them, and every file imports what it needs. `hass` and `TZ` are mutable module variables; the module exports `getHass()`, `setHass()`, `getTZ()`, `setTZ()` and the class calls the setters where it assigned them. This is scaffolding that phase 2 deletes.
- CSS: `src/styles.js` imports each file with Vite's `?raw` suffix (amended in #69: `?inline`, so Vite minifies it; see As built (#69)) in the order `base, extra, tabs, phone, glass, lights, live, motion` and exports the joined string; the class injects it exactly as today.
- Version: `const VERSION = __VERSION__` with a Vite `define` that reads `package.json`. No file contains `'__VERSION__'` after this PR.

### Vite configuration

- `vite` as a dev dependency, pinned exactly. `vite.config.ts` with `build.lib: {entry: 'src/main.js', formats: ['es'], fileName: () => 'home-panel.js'}`, `build.outDir: 'dist'`, `build.emptyOutDir: true`, `build.sourcemap: true`, `build.minify: 'esbuild'`, `build.target: 'es2020'`, `build.rollupOptions.output: {chunkFileNames: 'chunks/[name]-[hash].js', assetFileNames: 'assets/[name]-[hash][extname]'}`.
- A tiny Vite plugin (or `vite-plugin-static-copy`) copies `vendor/*.js` and `vendor/*.css` into `dist/` so `loadScript(BASE + 'apexcharts.min.js')` and the Mermaid loader keep working unchanged. Spec 07 removes this.
- `define: {__VERSION__: JSON.stringify(pkg.version)}`; the release workflow builds from the checked-out `package.json`, so no CLI version argument is needed.
- Scripts: `npm run build` runs `vite build`; `npm run dev` runs `vite build --watch`; `build.mjs` is deleted.
- Source maps (`home-panel.js.map`) MUST be included in `dist/` and in the release zip. The map MUST reference original paths under `src/`, not inlined sources, and MUST NOT include `sourcesContent` from `node_modules` of any size that would matter (default settings satisfy this).

### Size budget

- `size-limit` with `@size-limit/file`, checking `dist/home-panel.js` gzipped. The budget is the first minified build's size plus ten percent, rounded up to the kilobyte, written in `package.json` with a comment line in the PR explaining the number. `npm run size` runs it; CI runs it after the build and fails on overrun.
- The budget MUST NOT be raised later without a changeset explaining why. It MAY be lowered.

### Tests

- The unit tests replace the source-text loader with `import {resolveConfig} from '../../src/config.js'` and the equivalent for `stack.js` and `fr.js`. The French tests' fake `hass` is passed through the new `setHass()` of the legacy globals module.
- `build.test.mjs` becomes `dist.test.mjs`: it asserts that `dist/home-panel.js` exists after `npm run build`, parses (`node --check`), contains the package version string once, contains no placeholder marker, has a `.map` beside it whose `sources` list includes `src/config.js`, and that the vendor files are present. The personal-data scan runs over `src/**`, `test/**` and `dist/home-panel.js`.
- The harness server serves `dist/` under `/panel/` as before, including `chunks/` and `assets/` subpaths.
- The screenshot baselines MUST pass unchanged. The Playwright behaviour suite MUST pass.

### Type checking and lint

- `tsconfig.check.json` extends its `include` to every file under `src/` with `checkJs` but **not** `strict` for the legacy files: a second config, `tsconfig.legacy.json`, with `strict: false`, `noImplicitAny: false` covers `src/home-panel.js`, `src/auto.js`, `src/i18n/fr.js` and `src/legacy/globals.js`, so that broken imports and typos in names are caught while the mass of untyped code is tolerated. `npm run typecheck` runs both.
- ESLint's `import` resolution is enabled so an unresolved import is a lint error.

## Acceptance Criteria

1. `grep -rn "__CONFIG__\|__STACK__\|__FR__\|__AUTO__\|__CSS__\|'__VERSION__'" src build.mjs` returns nothing, and `build.mjs` does not exist.
2. `npm run build` produces `dist/home-panel.js` (minified), `dist/home-panel.js.map`, and the vendor files; `dist/home-panel.js` is smaller than what `build.mjs` produced. Amended in #33: the goal was "at least 40 percent smaller than the 571 KB produced today", but `build.mjs` produced 675,832 bytes by then and minification cannot reach 40 percent; the Vite build is 505,406 bytes (25.2 percent smaller, 20.4 percent gzipped), and the size budget of #35 starts from it. See "As built (#33)".
3. `npm run size` passes and the budget is recorded in `package.json`.
4. The visual project passes with no baseline updated; the Playwright behaviour suite passes; `npm test` passes with no `new Function` left under `test/`.
5. `npm run typecheck` passes (both configs) and `npm run lint` passes.
6. Opening the test house in Chromium DevTools with source maps on shows `src/home-panel.js` and `src/config.js` as original sources.
7. The release zip from the workflow contains `home-panel.js`, `home-panel.js.map` and the vendor files at its root.

## Notes

- `es2020` as the target keeps optional chaining and nullish coalescing untouched and lowers nothing the code uses today; it matches the iPad Safari versions a wall tablet is likely to run. Raise it only with a reason.
- Vite's library mode does not inject CSS; that is why the CSS is imported as text (raw, amended in #69 to `?inline`, minified) and injected by the class exactly as today. Phase 3 moves styles into Lit components.
- The `legacy/globals.js` module exists to make the imports honest without rewriting logic. Its exports list is the inventory of module-level state phase 2 must remove; keep it short and do not add to it.

## As built (#33)

Where the build in the repository differs from the plan above, and why. The plan stays as written; this is the record.

- **Vite 8, not 7.** `vite` is pinned at 8.3.6 (the version Vitest 5.1.0 already installs, so there is one copy) and `vite-plugin-static-copy` at 4.1.1; both accept Node `^22.12`. Vite 8 bundles with Rolldown and minifies with Oxc, so `build.rollupOptions` is `build.rolldownOptions` and `build.minify` is `'oxc'` (Vite 8's default). `minify: 'esbuild'` would need the `esbuild` package as a further dependency and is deprecated in Vite 8.
- **Library mode keeps an ES entry's whitespace.** For an `es` library Vite turns Oxc's whitespace step (`codegen`) off and keeps `compress` and `mangle`, so that the consumer's bundler can still shake the file. This entry is the final file Home Assistant loads, so `vite.config.ts` sets `rolldownOptions.output.minify: {codegen: true}`, which Vite merges into its own settings; without it `dist/home-panel.js` is 568 KB of tab-indented code.
- **`target: 'es2020'` lowers nothing.** A build with `target: 'esnext'` differs from it in five places only, where the minifier would write `&&=` or `||=` itself; the source uses no syntax that needs lowering.
- **The vendor copy keeps the files at the root.** The plugin keeps the `vendor/` folder in the destination unless told otherwise; `rename: {stripBase: 1}` puts `apexcharts.min.js` and the others beside `home-panel.js`, where `BASE + 'apexcharts.min.js'` looks. The dist test checks that they are byte for byte the files in `vendor/`.
- **Size: the 40 percent goal is not met, and acceptance criterion 2 is amended to the measured result.** The 571 KB in this spec is the plan's figure; before this PR `node build.mjs` produced 675,832 bytes (181,548 gzipped at level 9), after the Prettier pass (#25) and the work since. The Vite build is 505,406 bytes (144,567 gzipped): 25.2 percent smaller, 20.4 percent gzipped, and 11.5 percent under 571 KB. Forty percent under the old build would be 405,499 bytes. A minifier removes comments, whitespace and long names from code, and the code is now 193 KB; the rest is text it leaves alone: the stylesheet, one 153,956-byte string, and about 156 KB of HTML and French in other strings, of which only 1,578 bytes are line breaks and indentation. Getting to 40 percent means changing that text. Minifying the CSS with Lightning CSS (Vite 8 installs it) takes the stylesheet from 153,759 to 114,705 bytes, which still leaves the bundle near 466 KB (31 percent smaller), and it rewrites rules, shorthands and vendor prefixes. Measured: with no browser targets it drops 16 of the 19 `-webkit-backdrop-filter` declarations, so an older iPad would lose the glass; with Safari 15 targets it keeps them. The Chromium baselines cannot see either. That is the CSS minification follow-up (#69), not this ticket, whose stylesheet goes in as it is today; the size budget (#35) starts from this build.
- **The version is in the bundle once as a string.** The minifier keeps the `VERSION` constant once and folds it into the Mermaid URL where it is used (`mermaid.min.js?v=2.11.1`). The dist test counts the version as a string of its own and expects exactly one: a second would mean `src/legacy/globals.js`, and the `hass` it holds, was bundled twice.
- **`src/legacy/globals.js` is smaller than the plan's list.** It holds what `auto.js` and `fr.js` reached as globals, what depends on `hass` or the time zone, and what they need to compile: `getHass`, `setHass`, `getTZ`, `setTZ`, `VERSION`, `BASE`, `loadScript`, `st`, `ok`, `num`, `attr`, `kw`, `esc`, `ampm`, `fmtTime`, `fmtDate`, `localDay`, `hourNow`, `tile`, `plural`, `cap`. The pure helpers only the class uses (`sum`, `f1`, `f0`, `durTxt`, `fmtDay`, `ms`, `tiles`, `fold`, `shortNames`, `L0kw`, `ago`) stay in `home-panel.js`. `VERSION`, `BASE` and `loadScript` are there, not in the class file, because `auto.js` needs them and the class imports `auto.js`. The class reads `hass` and the time zone through `getHass()` and `getTZ()` everywhere, at the time of the call; nothing reads them when a module loads. `FR` is an exported live binding in `fr.js` with a `setFR()` for the one place that assigns it.
- **`FR_ATTR`, `frNode`, `frTree`, `frApex`, `FR`, `setFR`, `frText` and `FR_MAP`** are what `fr.js` exports; `fr-map.js` is merged into it.
- **Type checking is unchanged.** `tsconfig.check.json` still covers `types.d.ts`, `config.js` and `stack.js` (they now carry `export`); `tsconfig.legacy.json`, which covers the rest of `src/`, comes with #35 (the strict config stays narrow: `config.js`, `stack.js` and `types.d.ts`, nothing else). `src/env.d.ts` declares `__VERSION__`; ESLint knows it as a read-only global in `src/`.
- **Lint.** The cross-file `globals` list and `eslint.bundle.config.js` are gone: with real imports, per-file `no-undef` and `no-unused-vars` (now on top-level names too, since no file is a script any more) do what the bundle lint did, so `npm run check` no longer lints `dist/`. `import/no-unresolved` comes with #35; until then `vite build` fails on an unresolved import and on a name a module does not export (Rolldown's `MISSING_EXPORT`).
- **Tests: the loaders go here, not in #34.** `config.test.mjs` and `stack.test.mjs` import the modules instead of stripping `^export ` from their text as this ticket's minimal step had it: Vitest transforms a file that has `export` before it maps V8 coverage back to it, so a loader that evaluates the raw text no longer lines up and the report fell from 98.82 to 90.58 percent of statements. With imports the figure is 98.82 percent again. `i18n.test.mjs` imports `fr.js` and then passes its fake `hass` through `setHass()`, in that order as in the panel, so a `hass` read at import time fails the test; it does so on a fresh copy of the modules for each test, because `fr.js` caches the house's names for a minute. No `new Function` or `vm.compileFunction` is left under `test/`, which is #34's acceptance criterion. `dist.test.mjs` builds `dist/` itself when it is missing or older than a build input. `vitest.config.ts` defines `__VERSION__` like the Vite config does.
- **Visual scripts build on the host.** Rolldown's native binding is installed for the host's platform, so the `:docker` and `:container` scripts run `npm run build` on the host and only `npx playwright test --project=visual` inside Linux. The CI visual job does its own `npm ci` inside the image and keeps running `npm run test:visual`.
- **Source map.** "Not inlined sources" is read as a separate `.map` file rather than a `data:` URL inside the bundle. The map keeps `sourcesContent` on purpose: Home Assistant serves `www/home-panel/`, not `src/`, so DevTools needs the source text from the map. Its `sources` are relative paths under `../src/` only, which the dist test checks.
- **Release.** `release.yml` also checks that `home-panel.js.map` is in the zip, beside `home-panel.js`.

## As built (#69)

This is the one place that says why the stylesheet is minified the way it is; `vite.config.ts`, `src/styles.js` and `test/unit/styles.test.mjs` point here.

- **Browser floor: Safari and iOS 26, and current Chrome, Edge and Firefox** (README, Browser support). The owner decided that older Safari versions do not matter, which is what lets the stylesheet be minified without a prefix inventory.
- **The stylesheet is minified by Vite's own CSS pipeline.** `src/styles.js` imports the eight files with `?inline` (a string, after Vite has processed it) instead of `?raw`, and `vite.config.ts` sets `build.cssMinify: 'lightningcss'` (named, so that a change of Vite's default cannot switch the minifier) and `build.cssTarget: ['safari26', 'ios26', 'chrome140', 'edge140', 'firefox140']`. For these targets Lightning CSS drops the vendor prefixes they do not need: all 19 `-webkit-backdrop-filter` (Safari reads the unprefixed property from 18), `-webkit-mask-image`, and seven of the eight `-webkit-appearance`; it keeps the ones they still need (`-webkit-user-select`, `-webkit-line-clamp`, `-webkit-box`, the scrollbar, slider and `-moz-range-*` pseudo-elements and the rest). `css.transformer` stays at its default.
- **`lightningcss` is pinned beside Vite.** It is a `devDependency` at 1.33.0, exactly the version Vite 8.3.6 depends on (`^1.33.0`); `npm ls lightningcss` shows one deduplicated copy, which Vite loads from its own folder. `renovate.json` puts `vite` and `lightningcss` in one group ("Vite and Lightning CSS") and leaves both out of the `no-changeset` label, because a bump changes the shipped bytes; the group's pull request needs a changeset (or the label, by a person who has looked). If a Vite bump asked for a newer Lightning CSS than the pin, npm would nest a second copy under `node_modules/vite`, which the pin no longer governs; `styles.test.mjs` would still see what that copy does to the stylesheet.
- **Lightning CSS merges `backdrop-filter` and `-webkit-backdrop-filter` by position.** When a rule writes the unprefixed declaration first and the prefixed one second, it emits the prefixed one only, which Chromium does not implement (and which these targets would drop anyway); the idle stack card (`:is(.idle, .hstk) .sc`) lost its blur and four idle-clock baselines failed by 90 to 97 thousand pixels. Sixteen of the nineteen rules that carry both already wrote `-webkit-` first. The other three (`.hwx .hstk .sc` and `:is(.idle, .hstk) .sc` in `tabs.css`, `.app.tabsv.cp .rail` in `phone.css`) now do too; the swap changes nothing for any browser. Keep the prefixed line first in a new rule. Checked again with the modern targets: without the swap the stylesheet has 17 unprefixed `backdrop-filter` against 20 in the source.
- **The guard.** `test/unit/styles.test.mjs` builds the entry and the stylesheet alone (`src/styles.js`) into a scratch folder through Vite's API and the repository's `vite.config.ts`. It checks that the output is smaller than the source and is the string inside the entry, that no comment is left, that the unprefixed `backdrop-filter` count is the same as in the source (20) and no source rule writes it before the prefixed line, that every distinct `color-mix()` expression is still there (Lightning CSS merges two adjacent rules with the same declarations, `.pod.on` and `.mtvscreen.on` in `glass.css`, into one selector list, one `color-mix(` fewer and the same style), and that `@supports`, `@container`, `@layer`, nesting, `:is()`, `:where()` and `:has()` are there at least as often as in the source. It counts in the stylesheet string and not in `dist/home-panel.js`, because the JavaScript around it has a `backdrop-filter` and seven `color-mix(` of its own in inline styles. It fails with one of the three rules put back in its old order (`expected 19 to be 20`).
- **Rewrites Lightning CSS makes, all fine for these browsers.** `@media (max-aspect-ratio: 1/1)` becomes `(aspect-ratio<=1)` (range syntax, Safari 16.4+), `@container (max-height:230px)` becomes `(height<=230px)`, `rgba()` and `transparent` become `#rrggbbaa` and `#0000`, `flex: 1 1 260px` becomes `flex: 260px`, `:focus-visible` lists are wrapped in `:is()` or split, `::before` is written `:before`, `background: none` and `transparent` become `0 0`, and custom properties are rewritten like any value (the panel's JavaScript reads `--card`, `--f-body` and `--f-num` through `css()`, and ApexCharts and Mermaid read the new text as before). The source CSS is untouched apart from the three swapped lines.
- **Size budget: 153 kB of gzip.** Measured on `main` with the fonts, the ApexCharts stylesheet change, the Reduce Motion rules and the rest merged in, on Node 26 on a Mac: `npm run size` says 145.23 kB before (entry 507,088 bytes) and 137.92 kB after (entry 467,282 bytes, 7.8 percent less). In CI, the Playwright image on Node 24.20, the same build says 138.35 kB: the figure to compare with. 138.35 kB plus 10 percent is 152.2 kB, rounded up to 153 kB (the limit was 160 kB). ## As built (#98)

- **A `.br` and a `.gz` beside every script.** The `precompress` plugin in `vite.config.ts` (a `writeBundle` hook, so the files are on disk and the `//# sourceMappingURL` line is in what is compressed) writes `X.js.gz` (`zlib.gzipSync`, level 9) and `X.js.br` (`zlib.brotliCompressSync`, quality 11, text mode, size hint set to the file's length) for the entry and every chunk: 91 scripts, 182 new files. Node's `zlib` writes no timestamp, so the output is reproducible. No dependency was added. The `.map` files, the fonts and `LICENSES.md` get none: only DevTools fetch the maps, and woff2 is compressed already. The extra build time is about 5 seconds (brotli at quality 11 on 3 MB of JavaScript); the build is 6 seconds in all.
- **Why this is enough (verified on 2026-11-08 from the sources, not run live).** Home Assistant registers `<config>/www` as `StaticPathConfig("/local", local, cache_headers=not is_dev)` (`homeassistant/components/frontend/__init__.py`); `http/server.py` gives it `CachingStaticResource`, whose `_handle` returns aiohttp's `FileResponse` (`http/static.py`) and only adds `Cache-Control: public, max-age=2678400`. `FileResponse.prepare()` (`aiohttp/web_fileresponse.py`) looks for a sibling in the order `ENCODING_EXTENSIONS = {".br": "br", ".gz": "gzip"}`, takes the first whose encoding is in the request's lowercased `Accept-Encoding`, and serves it with `Content-Encoding`, `Vary: Accept-Encoding` and the `Content-Type` of the uncompressed name. That is in aiohttp 3.9, 3.11 and 3.13 (Home Assistant pins 3.11.11 in 2025.1 and 3.14.5 on `dev`). So the zip only has to carry the files; `release.yml` needed no change. HACS mounts `/hacsfiles` the same way, but it is not the install path here and nothing depends on it.
- **The stale-sibling rule.** aiohttp makes no mtime check: a `.br` or `.gz` is served for as long as it exists, so a new `home-panel.js` copied over an old folder would be shadowed by the old compressed copy. Chunk names carry a hash, so only `home-panel.js` is exposed. The README (Install, step 2) says to replace the whole `home-panel/` folder.
- **Release zip.** Run locally with the workflow's own commands: 355 files, the `diff` of `dist/` against the zip is empty, and `home-panel.js`, `home-panel.js.map`, `LICENSES.md`, `chunks/`, `fonts/` and the 182 compressed copies are in it. The zip is 3,048,133 bytes without the copies and 5,345,155 with them (+2,297,022).
- **The guard.** `test/unit/dist.test.mjs` lists the `.br` and `.gz` of the entry and of every chunk in its exact file list (and no other `.br` or `.gz`), and a new test decompresses each one (`gunzipSync`, `brotliDecompressSync`) and compares it byte for byte with its script. Seen failing: with one `.br` deleted the list test and the round-trip test fail; with one `.gz` cut to 1,000 bytes the round-trip test fails. `size-limit` measures `dist/home-panel.js` by itself and is unaffected. `test/e2e/server.mjs` is unchanged: it serves the plain file for a `.js` URL (it never looks for a sibling), so the specs and the baselines see the same bytes as before.
